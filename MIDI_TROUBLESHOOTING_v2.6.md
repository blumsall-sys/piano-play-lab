# Cleo's Piano Play Lab v2.6 – USB MIDI troubleshooting

## Important distinction

Selecting **M-Audio Keystation Mini 32 MK3** only changes the visual keyboard and which input the game expects. Chrome must separately grant Web MIDI access. The app now requests access when the layout is explicitly selected, and offers a prominent Connect / Reconnect button in **Settings** and **Practice**.

## Windows / Chrome first-time setup

1. Plug in the M-Audio controller before opening Chrome. It is class-compliant and does **not** require an extra driver or music program in supported Windows versions.
2. Confirm Windows detects it under **Device Manager → Sound, video and game controllers** (sometimes listed as USB Audio Device / Keystation).
3. Run `START_WINDOWS.bat`, open `http://localhost:8000/`, and in Settings select **M-Audio Keystation Mini 32 MK3**.
4. When Chrome requests access to MIDI devices, choose **Allow**. If no prompt appears, press **Connect USB MIDI keyboard** or **Scan / reconnect** in Settings. Current Chrome requires permission even for normal notes, not only SysEx.
5. The status should say **Ready** and list the device, including its connection state. Press a physical key. The **Last MIDI event** field should update with the key's note and velocity.
6. Next click **Identify leftmost C** and press the controller's far-left C. The app labels its 32 keys using the note received; if a lesson needs a note outside the current 32-key window, use the keyboard's physical octave up/down buttons.
7. Go to Practice. **MIDI connected** should appear above the keyboard. Audio is generated by the browser unless you disable MIDI sounds in Settings.

## If MIDI is unavailable or denied

- Use **Chrome or Edge** on the Windows laptop. The site must be served over **HTTPS** (GitHub Pages) or `localhost`; an unencrypted phone/tablet LAN address may not grant MIDI access.
- In Chrome, click the site information icon beside the address → **Site settings** → **MIDI devices** → Allow; reload and reconnect.
- GitHub Pages works as an HTTPS site. Embeds in iframes may require explicit MIDI Permissions-Policy delegation; test the site directly first.
- If 0 devices are listed even after permission: use a working USB **data** cable (M-Audio uses a mini-USB connection), connect directly to the computer, try another USB port, and inspect Device Manager. Close music apps that might hold the MIDI device.
- If a device is listed but won't open, close programs using MIDI, unplug/replug and click Scan / reconnect.
- Open [`midi-test.html`](midi-test.html) in Chrome to test hardware independently of game scoring. If its raw MIDI events do not appear, the problem is at the browser/OS/cable layer, not the lesson logic.
- On Android, USB-C OTG support, a powered adapter/hub, and browser Web MIDI support are required; test Windows first.

## What was changed in v2.6

- Added MIDI connection buttons in Settings and Practice; selecting M-Audio explicitly also requests permission.
- Explicit port open, reconnection listeners and hot-plug awareness.
- Last-received MIDI note/velocity indicator and port diagnostics.
- Clear errors for unsupported browsers, insecure pages, denied permissions, zero discovered devices and port open failures.
- Independent `midi-test.html` hardware test page.
- Retained Hape F3–F5 layout, M-Audio 32-key layout, progress, MIDI velocity, chords, timing, and three-pass Rhythm Highway.

**This package was tested with simulated browser MIDI inputs, not a physically connected M-Audio keyboard.**
